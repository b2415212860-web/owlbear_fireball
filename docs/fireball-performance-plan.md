# Owlbear 火球术扩展实施计划书

版本：1.0 · 日期：2026-09-05 · 实施更新：2026-09-06 · 状态：已实现 1.2.0 Owlbear 专用本地候选版，真实房间验收待完成

> 最新实施记录见 [1.2.0](release-1.2.0.md)，上一轮见 [1.1.0](release-1.1.0.md)。下文保留原计划；其中“当前基础”描述实施前版本，不代表新代码。已落地原生瞄准、可见特效页握手与恢复、两槽并发限流、模拟回归和子路径构建。1.2.0 按用户最新要求只构建 Owlbear 版本，并加入圆形火球、连续尾焰、爆裂、冲击波、局部体积蘑菇云及缩放像素预算，不再构建演示入口。尚未证明真实 Owlbear 透明层兼容性及房间帧率达到本文目标，不作为已通过 P0/P5 的发布声明。

## 1. 项目目标与优先级

交付一个可以安装到 Owlbear Rodeo、在真实房间中稳定完成施法、对地图操作影响较小的火球术扩展。采用 Three.js 作为首选特效渲染器，先验证 Owlbear 集成可行性，再完成视觉效果。

优先级依次为：完整释放流程、地图操作顺畅、定位准确、多人可见、电影感。本文中的帧率、延迟和资源数量均为待测验收目标或初始预算，不代表现有版本已经达到，也不承诺所有设备都能达到。

首版保留以下体验：

- 界面右上角悬浮“火球术”按钮；无场景时显示不可用状态。
- 明确选定一个施法棋子；点击按钮后移动半径 20 英尺的圆，再点击地图释放；Esc 或取消操作退出瞄准。
- 连贯显示立体火球、拖尾、命中闪光、紧凑的俯瞰蘑菇云和余烬。烟雾逐渐消散，结束后恢复可施法状态。
- 房间内启用扩展的在线玩家在各自地图视角中看到同一次施法。
- 提供自动、标准、省电画质；错误可见、可以恢复。

首版范围不包含伤害掷骰、豁免、法术位、墙壁碰撞或遮挡、动态雾计算、地面裂缝、持久地形改变及音效。20 英尺是几何范围，动画不是伤害判定。烟云采用分层贴图模拟体积感；重型实时体积模拟列为后续可选研究。

## 2. 当前基础与需要澄清的问题

本地项目已有按钮、瞄准、坐标换算、广播和 Three.js 网页演示，可以复用。当前接入 Owlbear 的后台分支使用 SkSL Effect，与网页 Three.js 演示是不同渲染路径。工作区已有未提交的电影特效改动，实施时应先记录现状并保留，不能直接覆盖。

2026-09-05 上一轮公网检查中，线上入口引用 `background-CQecrMB1.js`，本地构建引用 `background-BTixKYGO.js`；线上爆炸约 1.05 秒，本地新版约 4.4 秒。实施开始时需重新核对实际部署版本，这些指纹不作为永久版本标识。

已确认的代码问题是：动画依靠每帧 SDK 更新、缺少统一施法状态、错误主要留在控制台、未限制广播触发的并发播放、实际房间测试覆盖不足。

尚不能定论的原因包括：后台 iframe 动画调度停顿、SDK 往返延迟、着色器首次编译、GPU 填充负载及宿主地图本身过重。特别是浏览器通常会暂停隐藏 iframe 或后台标签页的 `requestAnimationFrame`；现有动画由后台页面驱动，这可能直接影响播放完整性，需要实测。独立 iframe 也不保证独立 CPU 或 GPU 资源。[MDN：requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)

此前“1410×1410 世界尺寸等于固定 200 万个屏幕像素”的估算不能作为性能实测依据。实际开销取决于地图缩放、设备像素比、裁剪、宿主渲染实现和着色器复杂度，必须记录实际屏幕覆盖与帧时间。

## 3. 推荐技术方案

### 3.1 组件分工

| 组件 | 职责 | 约束 |
| --- | --- | --- |
| 后台控制器 | 场景生命周期、按钮状态、消息校验、去重、播放调度 | 不承担逐帧视觉动画 |
| 右上角按钮 | 进入瞄准、取消、显示加载/施法/错误状态及画质设置 | 状态来自控制器 |
| Owlbear 原生工具模式 | 鼠标/触摸定位、20 英尺本地范围圈、确认与取消 | 使用世界坐标，保留原工具以便退出恢复 |
| `fx.html` 透明页面 | 一个 Three.js renderer、本地飞行与爆炸、画质调整 | 动画帧内不调用 Owlbear 场景写接口 |
| 坐标适配器 | 世界坐标映射到每位玩家屏幕、低频视口采样 | 同时最多一批未完成采样 |
| 共享特效核心 | 时间线、材质、粒子池和清理逻辑 | 网页演示与 Owlbear 调用同一套实现 |

优先使用原生 Tool API 做瞄准。官方工具模式支持交互回调，避免用整屏网页接管地图的所有点击；右上角按钮依旧是用户的主要入口。预览使用本地圆形图元，移动更新合并为每秒最多 20 次、每次仅保留最新位置，不对房间广播预览；具体绘制和交互顺畅程度在 P0 验证。[Owlbear Tool API](https://docs.owlbear.rodeo/extensions/apis/tool/)

Three.js 特效候选载体为全屏 Modal，使用 `fullScreen`、`hideBackdrop`、`hidePaper` 和 `disablePointerEvents`。官方提供这些配置，但“模态层不响应指针”不能直接证明地图拖拽、键盘焦点、Esc 和其他扩展弹窗全部兼容，必须通过阶段 P0 验证。当前 SDK 没有通用 `modal.update` 方法，不把反复重开 Modal 当成逐帧开关。[Owlbear Modal API](https://docs.owlbear.rodeo/extensions/apis/modal/)

### 3.2 生命周期与就绪握手

首选会话内复用一个通过 P0 验证的透明页面：进入场景后低优先级初始化，空闲时透明清屏、停止绘制；卸载或离开场景时释放。这个方案只有在页面不抢焦点、不干扰其他弹窗时才能保留。

若常驻 Modal 不兼容，则测试按次打开、预热、播放、关闭的方案；代码和纹理可利用浏览器缓存，但关闭 iframe 后不能承诺 GPU 资源仍然保留。按次创建造成的首次延迟同样纳入验收。两种方式均不通过时，停止扩大 Three.js 集成，记录失败依据并采用轻量原生 Effect 兼容路径。

页面创建后先注册消息处理，完成材质/纹理准备与试绘，再向控制器发送带实例 ID 的 `READY`。控制器收到后发送 `PLAY`，渲染页回报 `STARTED`、`IMPACT`、`FINISHED` 或 `ERROR`。打开页面的 Promise 成功不等同于 renderer 就绪。待发送事件有数量和时限上限，避免“广播早于监听器”导致首次释放丢失。

使用有限预热和资源复用降低首次停顿。Three.js 的预编译能力按当前安装版本检测，不能用后台持续绘制来预热。卸载时显式释放材质、几何体、纹理、渲染目标与监听器。[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)、[Three.js 资源释放](https://threejs.org/manual/en/cleanup.html)

### 3.3 坐标与地图交互

范围始终为 20 英尺，即 5 英尺网格下半径四格。网格 DPI 与英尺/米单位换算复用现有几何模块。画质降低只改变像素密度和装饰细节，不缩小实际瞄准半径。

官方 Viewport API 提供坐标转换、位置和缩放读取；当前文档及本地 SDK 3.1.0 未提供视口变化订阅。因此不能依赖假设的 `viewport.onChange`。[Owlbear Viewport API](https://docs.owlbear.rodeo/extensions/apis/viewport/)

实现时用官方 `transformPoint` 校准映射，验证左上、中心、右下及不同缩放下的结果。瞄准圈由原生世界坐标图形跟随地图；播放期间以最多 10 批/秒采样原点投影和缩放，缓存后交给 Three.js 使用，不在每个粒子或每帧中请求 SDK。采样慢时跳过新请求，禁止排队堆积。独立读取不是原子快照，需标记采样序号与耗时，丢弃旧批次，并实测快速缩放时的不一致。桌面视口稳定后命中中心误差目标不超过 4 CSS 像素。

透明层没有地图深度、墙壁或雾的渲染信息；其火球、烟雾和发光只是叠加画面。后处理仅作用于特效自己的画布，不能自动扭曲或照亮下面的地图。快速平移/缩放时可能存在短暂跟随延迟；以 P0 实测决定是否能接受，不能通过锁住用户地图操作掩盖。

## 4. 完整施法流程

| 状态 | 用户看到的内容 | 下一步与恢复方式 |
| --- | --- | --- |
| 未就绪 | “请打开场景”或“正在准备” | 场景和必要资源就绪后进入待机 |
| 待机 | 右上角“火球术”按钮 | 检查选中的施法棋子，保存起点，进入瞄准 |
| 瞄准 | 跟随指针的 20 英尺圈、“点击释放 / Esc 取消” | 点击锁定目标；取消则移除范围圈、恢复原工具 |
| 准备播放 | 保留已确认位置与“正在准备”提示 | 获得本地 READY/STARTED 确认后进入飞行；超时则明确报错 |
| 飞行 | 可辨识的立体火球和拖尾，约 0.55～0.85 秒 | 时间线到达目标，触发一次命中 |
| 爆炸与余烟 | 快速闪光、紧凑烟冠、余烬，约 1.4～2.0 秒 | 完成后清屏、解锁按钮；总播放约 2～3 秒 |
| 恢复或错误 | “再次释放”或具体错误提示 | 释放临时资源、清除锁；无需刷新整个房间 |

未选棋子时提示“请先选中施法棋子”，不再无提示地从视口中心发射。多选时要求选定一个起点。起点在进入瞄准时固定，并在确认前验证棋子仍存在；射程限制暂不加入。

每次施法有唯一 `castId`，阶段切换由一个控制器管理，清理操作可重复执行。按钮锁定覆盖本人整个施法；连续点击不会产生多个任务。本人操作状态与远端效果调度分离，远端播放完成不能意外解锁本人尚未完成的施法。首版本机仅保留一个完整烟云；多人碰撞触发时保留已有完整动画，额外施法用小型火球/命中提示降级，限制至两个额外简化效果，超出时合并计数提示，禁止无限排队或悄悄中断已有动画。

场景关闭、切换、扩展卸载、WebGL 上下文丢失和标签页隐藏均有清理路径。返回标签页时按截止时间丢弃过期效果并恢复状态，不从中途补播一堆旧火球。异步返回必须核对场景会话 ID 和渲染实例 ID，防止旧场景的迟到回调在新场景继续执行。

## 5. 多人消息与可靠性

房间广播发送一次施法参数；本机的控制器和特效页面之间允许少量就绪与阶段确认消息，均不逐帧发送。消息字段包括协议版本、场景会话标识、`castId`、起终点、世界半径、随机种子和时间线配置。场景标识应使用实施时验证过的可靠来源；不能假设存在未公开的 `OBR.scene.id`。

每位玩家从相同参数开始本地动画，画质可以不同，几何起终点和命中逻辑一致。首版目标是各自完整播放和尽量接近的触发时刻，不承诺严格同时命中。不能直接比较不同设备的 `performance.now()`；没有时钟校准前也不能将本机系统时间当成可靠的跨设备同步时钟。

广播是临时消息，官方上限为 16 KB；本项目每条施法载荷目标小于 1 KB。控制器检查连接来源、字段类型、数值有限性、合理范围、重复 ID、过期会话和速率。本地发送者也通过相同入口处理，避免“直接播放一次、收到 ALL 又播放一次”。广播发送成功不等于所有远端已经播放，不做无限重试；未启用扩展或晚加入的玩家不会重放旧施法。[Owlbear Broadcast API](https://docs.owlbear.rodeo/extensions/apis/broadcast/)

## 6. 特效设计与性能预算

用可辨识的阶段节奏营造力度：先见到有体积的火球和拖尾，再出现短促冲击，随后烟冠翻卷、冷却与消散。云团保持俯瞰视角，不生成面向屏幕的侧视蘑菇柄。

首版烟冠采用少量带明暗的纹理层或贴图序列，按高度、旋转和缩放形成翻卷体积感。火星用合批 Points/实例化四边形，按种子在 GPU 上计算运动；烟层控制透明重叠。几何体、材质和数组复用，避免每帧创建大量对象。合并渲染批次可以减少逐对象绘制开销。[Three.js 对象优化](https://threejs.org/manual/en/optimize-lots-of-objects.html)

| 项目 | 标准档初始预算 | 省电档初始预算 |
| --- | --- | --- |
| 绘制缓冲区 | 总像素不超过约 1600×900 | 不超过约 960×540 |
| 实际像素比 | 不高于 1，超出总像素预算继续降低 | 不高于 1，按预算降低 |
| 火星/碎屑总数 | 约 240～320 | 约 80～120 |
| 拖尾采样点 | 32 | 16 |
| 烟层数量 | 约 8～12 | 约 4～6 |
| 绘制调用 | 特效总计目标不超过 15 次/帧 | 目标不超过 10 次/帧 |
| 后处理 | 默认发光贴图；可选局部低分辨率 Bloom | 关闭 Bloom |
| 实时体积步进、阴影、物理引擎 | 首版不启用 | 不启用 |
| 空闲状态 | 0 次持续绘制 | 0 次持续绘制 |

上述分辨率为 GPU 绘制缓冲区上限，CSS 覆盖区域仍可以占满视口并保持正确坐标。优先裁剪到可见轨迹/爆炸区域；不能只调用 scissor 就假设所有后处理也省下了同等开销。首版无全屏多通道 Bloom。

自动档保守启动，按滑动窗口帧时间降分辨率、减烟层、减粒子。降级后当前施法不升档，避免画面反复抖动；后续施法再评估。判断整段与命中阶段的帧时间，不能只看平均 FPS。WebGL 不可用时以 Canvas 2D 简化渲染完成同一时间线；覆盖层兼容性不成立时，此替代渲染器也不能解决集成问题，必须回到 P0 的原生兼容方案。

P0 是技术方案的决策点。若透明层与地图操作不兼容或频繁重开不可接受，应在此收敛为轻量原生 Effect 版本，再评估 Three.js 的后续改进；不带着已知集成问题继续打磨昂贵烟雾。排期在 P0 完成后估算，避免把未验证的 API 假设转化为固定交付承诺。

## 8. 验收方法与门槛

### 8.1 测试环境

桌面首发覆盖当前稳定 Chrome、Edge；至少实测用户目前出现卡顿的设备和一台集成显卡笔记本。Firefox、Safari 和移动触屏列入兼容测试，只有实际测过才标记支持。浏览器硬件加速关闭或 WebGL 不可用必须走简化路径，不纳入 Three.js 标准档帧率保证。

固定场景 A：2048×2048 静态地图、约 50 枚静态棋子、5 英尺网格、关闭额外动态效果。场景 B：用户实际使用的地图、雾和常用扩展。记录分辨率、DPR、浏览器、CPU/GPU、地图缩放、效果实际屏幕面积与硬件加速状态。

同一设备依次测扩展关闭、启用后空闲、瞄准、飞行、爆炸、清理六种状态，分别记录宿主地图和特效 iframe 的表现。基线先稳定 10 秒，再记录 30 秒；动画指标只汇总实际播放区间，单独报告飞行和命中阶段，不能把施法间的空闲帧计入平均数。单独网页流畅不能替代真实 Owlbear 测试；只测特效自己的 FPS 也不能证明宿主地图不卡。

### 8.2 发布门槛

| 验收项 | 目标与判定方式 |
| --- | --- |

延迟与帧率用浏览器 Performance 记录、渲染器计数及阶段时间戳交叉验证；计数与阶段日志仅在诊断模式启用。跨设备时差若未做时钟校准，用同屏录像或明确的测量方法记录，避免直接相减各设备的时间戳。

有意义的自动化覆盖包括状态转移、取消/超时、重复消息、先消息后 READY、过期会话、隐藏后恢复、单位换算及构建资源完整性。SDK 模拟测试用于证明控制逻辑，真实房间用于证明宿主行为和性能，两者不能互相替代。

## 9. 文件调整与部署安排

计划扩展现有 `background.ts`、`button.ts`、`types.ts` 和 `geometry.ts`，把 `target.ts` 的输入接入原生工具模式；将 `three-fx.ts` 中可复用效果抽为渲染核心，新增控制器、坐标适配器、画质配置及 `fx.html` 入口。旧 `effects.ts` 仅在需要原生兼容路径时重构保留。实际命名在 P1 确定，优先保持模块职责清楚。

发布继续使用现有同域名 `/fireball/` 静态部署，服务器职责为 Nginx 托管 dist，渲染在玩家浏览器执行，不增加服务器 Three.js 进程。

每个发布版本提供 manifest 版本号和可检查的构建 ID。JS/CSS 使用哈希文件名；manifest 和 HTML 同时配置源站及 CDN 不缓存或可靠的短期重验证，不能只改源站就假设 CDN 会遵守。CORS 仅用于扩展公开资源，页面允许 Owlbear 嵌入。

上传时先准备完整版本目录再切换入口，保留前版哈希资源用于已有客户端和回退。若 Docker 直接绑定某个 dist 目录，重命名宿主目录后容器可能仍看到旧挂载，发布方式必须与挂载布局一起验证；采用挂载稳定父目录或明确重建容器的流程，不盲目依赖宿主目录替换。

每次部署后验证 manifest、所有 HTML、JS/CSS 和纹理；必要时刷新 CDN 的 `/fireball/` 目录“全部资源”，再核对构建 ID。测试用扩展 ID、广播频道与正式版隔离，避免新旧扩展同时收到消息重复播放。

最终交付物为：可安装的 dist 压缩包、共享 Three.js 渲染源码、基础兼容路径、自动测试结果、真实房间演示录像、设备性能记录、已知限制及部署回退说明。本文交付的是实施方案，尚未执行重构、上线或声称通过运行验收。
